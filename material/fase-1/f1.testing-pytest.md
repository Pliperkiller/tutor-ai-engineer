# f1.testing-pytest — apuntes

## Parte 1 (sesión 12, 2026-08-07)

### Por qué existe pytest
Verificabas la API con 8 `curl` a mano. Eso no se repite solo, nadie más lo
puede correr, y depende de que te acuerdes del caso raro (el 500 de S11 lo
encontraste de casualidad). Un test es ese curl escrito una vez y ejecutado
para siempre por algo que no se cansa.

### Las tres piezas

**El test**: función `test_*` con un `assert` pelado. Sin clases obligatorias,
sin `assertEqual`. pytest reescribe el assert para mostrarte los dos lados al
fallar.

**`TestClient`**: hace la request contra tu app **sin levantar servidor ni
tocar la red**. Sin puerto, sin `fastapi dev` en otra terminal.

```python
def test_health_returns_ok(client):
    response = client.get("/health")
    assert response.status_code == 200
    assert response.json() == {"status": "ok"}
```

**La fixture**: función que prepara lo que el test necesita, y que pytest llama
por ti. Es **el mismo patrón que `Depends` de FastAPI**: declaras, no llamas.
La diferencia es cómo se pide — en pytest, **el nombre del parámetro ES la
petición**.

```python
@pytest.fixture(autouse=True)
def reset_models_store():
    original = MODELS.copy()
    yield                    # <- pytest corre el test aquí
    MODELS.clear()           # <- teardown: corre aunque el test falle
    MODELS.update(original)
```

- Antes del `yield`: setup. Después: teardown.
- `autouse=True`: se aplica a todos sin que nadie la pida. Se usa para limpieza,
  cuando no te interesa recibir el objeto sino que el mundo quede limpio.
- Sin `yield` (con `return`) para las que no necesitan limpiar, como `client`.

### `conftest.py`
El archivo que pytest importa solo. Nombre exacto y obligatorio.
1. Fixtures compartidas **sin import** — los tests las piden por nombre.
2. Alcance por directorio y subdirectorios.
3. Corre **antes** que los archivos de test. Única ventana para preparar el
   mundo antes de que se importe el código bajo prueba.

### Generadores (lo que hace funcionar al `yield`)
- `yield` convierte la función en generador: **llamarla no ejecuta nada**, te
  devuelve un objeto congelado.
- `return` destruye el frame; `yield` lo **congela** (variables locales y
  posición siguen vivas).
- `next(g)` reanuda ese generador hasta el siguiente `yield`. `StopIteration`
  cuando se acaba. Un `for` es azúcar sobre `next()` + capturar `StopIteration`.
- Llamar la función **otra vez** crea un generador NUEVO, con frame propio.
  **Ese es todo el mecanismo del aislamiento entre tests**: pytest no hace
  `next()` sobre el generador viejo, llama la fixture de nuevo.
- Familia de `await`: funciones que se suspenden y se retoman. Las corrutinas de
  asyncio se construyeron históricamente sobre generadores.

### Identidad vs. contenido (el bug del día)
Copiaste el dict `MODELS` dentro de `conftest.py` en vez de importarlo. Tu
fixture limpiaba religiosamente **un objeto que nadie usaba**.

```python
d = {1: "a"}
otro = d
d = {}          # reasignar: mueve TU etiqueta. otro sigue con {1: 'a'}
d = otro
d.clear()       # mutar: cambia el objeto. otro SÍ lo ve
```

`main.py` tiene su propia referencia y nunca la vuelve a mirar. Por eso la
fixture **muta** (`.clear()` + `.update()`) en vez de reasignar. Y por eso
`from main import MODELS` es obligatorio: te ata al mismo objeto.

### El import ejecuta el módulo entero (P1, fallada)
Predijiste "fallarán los tests con dependencia de api key". Lo real: `main.py`
lee `os.environ["MODEL_REGISTRY_API_KEY"]` en la línea 42, **al importarse**.
`conftest.py` importa `main` → `KeyError` en la **colección**, antes de que
exista un solo test. No falla ninguno: **no corre ninguno**.

El arreglo va en `conftest.py`, físicamente encima del import:

```python
import os
# main.py lee la API key al importarse: la variable tiene que existir ANTES.
os.environ["MODEL_REGISTRY_API_KEY"] = "dev-secret-key"

from main import MODELS, app  # noqa: E402
```

Regla: un `noqa` nunca va solo, va con el comentario que explica por qué esta
línea es la excepción.

### Auditoría de mutación — el paso que casi nadie hace
**Un test verde no prueba nada hasta que lo ves ponerse rojo.** Rompes el código
a propósito, una rotura a la vez, y confirmas que la suite lo detecta.

| Rotura en `main.py` | Tests que cayeron |
|---|---|
| `404` → `200` en `get_model` | 2 |
| POST sin `dependencies=[...]` | 1 |
| `delete_model` sin `del MODELS[...]` | 1 |

Las tres detectadas: la suite es portante. Este es el antídoto exacto a los
asserts muertos de S7 (los que estaban dentro del `with pytest.raises` y nunca
se ejecutaban).

### Gestión de secretos (pregunta propia)
Lo del `conftest.py` **no es un secreto**: es un valor falso para un entorno
falso, y está bien que lo sea — la suite nunca debe tocar la key real.

Regla: **el código conoce el NOMBRE de la variable, nunca el VALOR.**

| Entorno | De dónde sale el valor |
|---|---|
| Tests | valor falso hardcodeado, en el repo |
| Dev local | `.env` gitignored, cargado con `pydantic-settings` |
| CI | secrets del repositorio inyectados como env vars |
| Producción | AWS Secrets Manager / SSM, Vault |

- `.env.example` **sí** se commitea: nombres y dummies, es la documentación de
  qué necesita el sistema para arrancar.
- `gitleaks`/`trufflehog` en pre-commit. Un secreto commiteado sigue vivo en la
  historia aunque borres la línea: la única respuesta seria es **rotar la key**.
- Fallar al arrancar si falta la variable es correcto. Lo peor es arrancar igual
  con un default.

### Dependencias: `--dev` o no
`uv add X` → `[project].dependencies`: lo que el **código** necesita para correr.
`uv add --dev X` → `[dependency-groups].dev`: lo que **tú** necesitas para
trabajar. El criterio no es el paquete, es **quién hace el import**: httpx es
runtime en el cliente async y dev aquí (solo lo usa `TestClient`).

Los corchetes son extras: `fastapi` a secas no trae uvicorn ni httpx;
`fastapi[standard]` sí. `uv tree` lo muestra con la marca `(extra: standard)`.
De 54 paquetes instalados, declaraste 3 — los otros 51 son prestados.
**Declara lo que importas**, aunque ya esté instalado por otra vía.
