# FastAPI — parte 1: primera API real (S10, 2026-08-05)

## Por qué existe
HTTP crudo = parsear texto de un socket. Flask (2010) dio enrutamiento pero
validación y docs quedaban a mano. FastAPI (2018) compone lo ya aprendido:
type hints (contratos) + Pydantic (validación) + async (concurrencia) →
validación automática, serialización a JSON y docs vivas en `/docs`.

## Piezas del día
- **Routing por decorador**: `@app.get("/ruta")` mapea verbo+ruta → función.
  Retornas dict/lista/modelo; FastAPI serializa a JSON (nunca `json.dumps`).
- **Path param tipado**: `{model_id}` en la ruta + `model_id: int` en la firma.
  FastAPI los conecta por nombre y VALIDA: `/models/abc` → 422 con
  `loc: ["path", "model_id"]` sin que la función se ejecute.
- **Body**: argumento tipado con un modelo Pydantic (`model: ModelIn`) = body
  del request. Llega ya validado y construido; nunca se parsea JSON a mano.
- **Errores**: `raise HTTPException(status_code=404, detail="...")` convierte
  excepción → respuesta HTTP. Validación fallida → **422** (no 400: el 400 es
  request malformado; 422 = JSON bien formado, contenido inválido) con el
  formato `loc`/`msg` de Pydantic.
- **Status de éxito en el decorador**: `@app.post("/models", status_code=201)`.
  201 Created = "ok y creé un recurso". Es parte de la DEFINICIÓN del endpoint
  (por eso va en el decorador y aparece en /docs). Solo camino feliz: 404/422
  mandan sobre él.
- **POST devuelve lo creado** incluyendo el `id` que asignó el servidor —
  si no, el cliente no sabe cómo pedir su recurso después.
- **`/docs`**: Swagger interactivo generado del código real (decoradores,
  firmas, modelos). No puede mentir porque no se escribe aparte.

## uv en serio (deuda S6 cobrada)
- `uv init --bare` → solo `pyproject.toml` (lo que PIDES: deps, requires-python).
- `uv add "fastapi[standard]"` → declara en pyproject + resuelve en `uv.lock`
  (lo que RESULTÓ: versiones exactas, transitivas) + instala en `.venv/`.
- `uv run fastapi dev main.py` → corre con el entorno del proyecto, reload
  automático. `.python-version` fija el Python POR PROYECTO (fix de raíz del
  problema pyenv/python3 del sistema).
- Lock nunca se edita a mano; `.venv/` nunca se commitea.

## Python del día
- Desempaque de dicts: `{"id": 7, **model.model_dump()}` funde los pares al
  mismo nivel. Clave repetida: gana la de más a la derecha.

## Errores y lecciones del día
- Asignación ingenua de ids: `max(MODELS.keys()) + 1` → con store vacío,
  `ValueError` no atrapado = 500; y al borrar el id más alto, el siguiente
  POST RECICLA el id (cliente con referencia vieja recibe datos ajenos con
  200 en vez de 404). Sistemas reales: contador monotónico (auto-increment).
- Higiene de predicciones: la hipótesis original se conserva y se ANOTA abajo
  (incluso "primera intuición X / tras pensarlo Y") — no se reescribe.

# FastAPI — parte 2: API key + mypy (S11, 2026-08-06)

## Por qué existe la API key
Sin auth, cualquiera con la URL escribe en tu API. Antes: confianza en la red
o Basic Auth (user:pass, pensado para humanos). Para máquina-a-máquina se
impuso lo simple: secreto estático en un header (convención `X-API-Key`) que
el servidor compara. Es el esquema de OpenAI/Anthropic/Stripe.

## Piezas del día
- **Inyección de dependencias (`Depends`)**: la función declara lo que
  necesita y FastAPI se lo trae. `dependencies=[Depends(verify_api_key)]` en
  el decorador = portero que corre ANTES del handler; si lanza, el handler
  nunca se ejecuta. Encadenable: endpoint → verify_api_key → api_key_header.
- **`APIKeyHeader(name="X-API-Key", auto_error=False)`**: objeto *callable*
  (clase con `__call__`) que solo EXTRAE el header del request. Se construye
  una vez al importar; FastAPI lo llama por request. `auto_error=False` →
  header ausente = `None` (tú decides el error, 401); con `True`, FastAPI
  rechaza solo con un 403 genérico. Verificado leyendo el código fuente.
- **El portero**: primero `if key is None → 401`, después
  `secrets.compare_digest(key, expected)` → 401 si no coincide; si coincide,
  la función termina sin más y el request pasa.
- **`compare_digest` vs `==`**: `==` corta en la primera diferencia → el
  tiempo de respuesta filtra la key carácter a carácter (timing attack).
  `compare_digest` tarda siempre lo mismo. Secretos → compare_digest.
  Explota con `None` (TypeError) — de ahí el None-check previo.
- **Key desde el entorno**: `os.environ["MODEL_REGISTRY_API_KEY"]` a nivel de
  módulo → si falta, el arranque MUERE (correcto: API "protegida" sin key
  configurada es peor que API caída). `os.environ` es `dict[str, str]`:
  las env vars siempre son strings.
- **DELETE**: `status_code=204` (sin body, la función devuelve None) + 404
  reutilizando el mismo criterio del GET.
- **/docs**: `APIKeyHeader` se registra como security scheme en el OpenAPI →
  botón *Authorize* automático; POST y DELETE marcados con candado.

## mypy (deuda de f1.python-profesional COBRADA)
- `uv add --dev mypy` (grupo dev, no producción) + `uv run mypy main.py`.
- Narrowing: tras `if key is None: raise`, mypy sabe que `key: str` y permite
  `compare_digest`. El chequeo de seguridad y el de tipos son EL MISMO.

## Errores y lecciones del día
- **El 500 fantasma (P1)**: primera versión sin None-check → `compare_digest(None, str)`
  → `TypeError` → 500. Exactamente el bug que mypy marca en `str | None`.
  Diagnosticado y corregido por el estudiante.
- **PowerShell**: `curl` es alias de `Invoke-WebRequest` → usar `curl.exe`;
  comillas JSON escapadas `\"`; env vars con `$env:NAME = "..."`, no `export`.
- P2 (reciclaje de ids al borrar el más alto) predicha BIEN — lección de S10
  asentada. `max(keys, default=0)` tapa el 500 del store vacío, no el reciclaje.

# S14 (2026-08-13) — Tu API como cliente de otra API

El patrón del capstone: la API deja de ser solo servidor y pasa a ser también
cliente de un servicio externo (hoy tasas de cambio; mañana la API de Claude).

```
curl --GET /models/1/cost?currency=EUR--> TU API --GET api.frankfurter.dev--> upstream
     <--   200 {"cost": 166.4}         --      <--  {"rates":{"EUR":0.867}}  --
```

## Upstream
El servicio del que dependes para responder. Tú eres downstream para tu cliente
y cliente del upstream. Los códigos 502 "Bad **Gateway**" y 504 "**Gateway**
Timeout" existen justo para decir "yo estoy bien, mi upstream no".

## lifespan — la fixture de la aplicación
```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    app.state.http_client = httpx.AsyncClient(timeout=2.0)   # startup: una vez
    yield                                                    # la app sirve requests
    await app.state.http_client.aclose()                     # shutdown: una vez
app = FastAPI(title="...", lifespan=lifespan)                 # <- el REGISTRO
```
- Misma mecánica que una fixture con `yield`: lo de antes es setup, lo de
  después es teardown, y el `yield` congela el frame mientras corre el trabajo.
- Antes se usaba `@app.on_event("startup"/"shutdown")`, hoy deprecado.
- `app.state` es un objeto libre para colgar cosas de vida larga.
- **Sin `lifespan=lifespan` la función existe pero nadie la llama**: `app.state`
  queda vacío y el primer endpoint que pida el cliente da `AttributeError`.
  Error cometido en S14 — el código estaba bien, faltaba el registro.
- Por qué un solo cliente: abrir un `AsyncClient` por request repite el
  handshake TCP+TLS y tira el pool de conexiones (medición de S9).

## Context manager
Objeto que define qué pasa al entrar y al salir de un bloque `with`
(`__enter__`/`__exit__`, o `__aenter__`/`__aexit__`). Existe para garantizar la
limpieza aunque el bloque lance una excepción — es un `try/finally` empaquetado.
`@asynccontextmanager` lo construye desde una función con un `yield`.
Ya usados: `async with httpx.AsyncClient()`, `with pytest.raises()`, `with respx.mock`.

## La dependencia que reparte el cliente
```python
def get_client(request: Request) -> httpx.AsyncClient:
    return request.app.state.http_client
```
`request.app` es la instancia de FastAPI, así que `request.app.state` es el
mismo `state` que llenó el lifespan.

## Traducir los fallos del upstream
```python
try:
    response = await client.get(url, params=...)
    response.raise_for_status()
except httpx.TimeoutException as exc:
    raise HTTPException(504, "Upstream timed out") from exc      # no respondió
except httpx.HTTPStatusError as exc:
    raise HTTPException(502, f"Upstream error: {exc.response.status_code}") from exc
```
Dejar escapar la excepción de httpx daría un **500**: le mentirías al cliente
diciendo que el roto eres tú. `ConnectTimeout`/`ReadTimeout` entran en el primer
`except` por herencia: ambas son subclases de `TimeoutException`.

## Testear todo esto sin red
- `respx` parchea el transporte **de red** de httpx. `TestClient` habla con la
  app por un transporte ASGI en proceso → respx **no** lo intercepta: tu request
  a tu app pasa, la llamada de tu app al upstream se finge.
- `with TestClient(app) as client:` es lo que dispara el lifespan. Un
  `TestClient(app)` pelado se salta el startup y `app.state` queda vacío.
- `return_value=httpx.Response(500)` para errores de status;
  `side_effect=httpx.ConnectTimeout("...")` para timeouts.
- La ruta mockeada sirve de espía: `route.called`, `route.call_count`,
  `route.calls.last.request.url.params`.

## Por qué la API llama al upstream y no el navegador
Para no exponer la API key, poder cachear, imponer timeouts/reintentos,
traducir errores ajenos y combinar datos propios con ajenos.

# Sesión 15 (2026-08-16) — leer un payload ajeno sin creerle

## La regla del día
Un JSON que viene de otro servicio **no es tuyo**: no controlas sus claves ni su
forma. Cada acceso con `[]` a ese payload es un `KeyError` potencial, y un
`KeyError` que escapa del endpoint se convierte en **500** — le dices al cliente
"me rompí yo" cuando la verdad es "el de enfrente me mandó algo raro" (**502**).

```python
rates = payload.get("rates", {})        # una sola lectura, con default
if symbol not in rates:                  # una sola guarda: cubre los dos casos
    raise HTTPException(502, "...")      # (rates ausente Y moneda ausente)
rate = rates[symbol]                     # ya es seguro
```

Orden importa: la guarda tiene que estar **antes** de la primera lectura. Una
guarda colocada después del acceso que pretende proteger es **código muerto** —
nunca llega a ejecutarse, porque ya reventaste.

## Nombrar un valor que se usa más de una vez
Error del día, cometido y sufrido en vivo: normalizar con `currency.upper()`
escrito en cada sitio donde hacía falta, en vez de una variable.

```python
symbol = currency.upper()   # una vez, arriba
```

Con 4-5 usos repartidos (params del request, la guarda, el lookup del rate, el
cálculo del cost, el campo de salida) son 4-5 sitios que deben estar de acuerdo.
Cada arreglo parcial dio un 500 distinto: primero un 502 falso con `?currency=eur`,
luego `KeyError` en `rate=`, luego `KeyError` en `cost=`. La variable elimina la
sincronización: no hay nada que olvidar.

## Guarda invertida — reaparición
```python
if not "rates" not in payload.keys():   # dos negaciones: dispara cuando TODO está bien
```
Antídoto: **lee la condición en voz alta como frase**. Quieres decir *"si rates
no está en el payload, error"* → `if "rates" not in payload:`. Si la frase leída
no coincide con la intención, la guarda está mal.

## El tipo de retorno del endpoint
```python
async def get_cost(...) -> CostOut:
    ...
    return cost_out          # NO cost_out.model_dump()
```
Anotar `-> CostOut` le da tres cosas a FastAPI: serializa por ti, **valida la
salida** contra el modelo, y publica el esquema de respuesta en `/docs`.
Serializando a mano las pierdes las tres. Y `model_dump_json()` devuelve un
*string*: FastAPI lo enviaría como JSON de un string (`"{\"id\":1,...}"`).

Hasta hoy solo se había modelado la **entrada** (`ModelIn`). `CostOut` es el
primer modelo de **salida**.

## Higiene: correr ruff ANTES de decir "listo"
Dos sesiones seguidas con basura del autoimport del editor en los imports:
`from asyncio import timeout` (S14) y `from pyexpat import model` (S15). Ninguna
la escribió el estudiante; ninguna la habría visto sin correr ruff.
También: `key not in dict` (no `.keys()`), y el `# noqa: B008` que acompaña al
`Depends(...)` en los defaults — idioma correcto de FastAPI que ruff no conoce.

## Entorno
`$env:VAR="valor"` es PowerShell. En **cmd.exe** es `set VAR=valor` (sin comillas,
sin espacios). En **bash**, las comillas invertidas de `-w "\`n..."` son
sustitución de comandos: ahí va `-w "\nHTTP %{http_code}\n"`.

## S16 (2026-08-25) — Cierre del endpoint externo: guardas, `Annotated` y salida tipada

### Guardas sobre un payload ajeno

Regla, en una frase: **una guarda menciona exactamente la clave que abre la línea de abajo.**
Dos aperturas encadenadas → dos guardas.

```python
payload = response.json()
# {'amount': 1.0, 'base': 'USD', 'date': '2026-08-24', 'rates': {'EUR': 0.85734}}

if "rates" not in payload:              # ¿existe el contenedor?
    raise HTTPException(502, ...)

if symbol not in payload["rates"]:      # ¿está mi moneda dentro?
    raise HTTPException(502, ...)

rate = payload["rates"][symbol]         # ahora sí, abrir
```

Sin las guardas, un payload inesperado da `KeyError` → **500** (culpa tuya).
Con ellas da **502** (culpa del upstream), que es lo que el contrato pide.

### Los dos errores cometidos hoy

1. **Adivinar la clave.** Se probó `"symbols"` — que es el nombre del *parámetro que se envía*,
   no una clave de la *respuesta*. La guarda era cierta siempre → 502 en el camino feliz.
   El payload estaba impreso dos mensajes antes.
2. **`in` sobre un string.** Se probó `"EUR" not in payload["base"]`, donde `payload["base"]`
   vale el texto `"USD"`. Sobre un dict, `in` pregunta por **clave**; sobre un string, pregunta
   por **subcadena**. No dio error: dio un 502 silencioso.

### `Annotated[X, Y]`

Significa: *el tipo es `X`, y además llevo pegado el dato extra `Y` para quien sepa leerlo.*
mypy y el editor solo ven `X`; FastAPI lee la `Y`.

```python
client: httpx.AsyncClient = Depends(get_client)              # etiqueta en el default
client: Annotated[httpx.AsyncClient, Depends(get_client)]    # etiqueta en el tipo  ← moderno
```

La segunda no tiene default, así que el parámetro es obligatorio y su posición ya no importa.
Es el mismo mecanismo que `Field(gt=0)` de Pydantic: colgar metadata a una declaración para que
otra herramienta la lea.

### `B008` de ruff es falso positivo en FastAPI

La regla existe por el default mutable clásico:

```python
def add(item, bag=[]):    # el [] se crea UNA vez, al definir la función
    bag.append(item)      # todas las llamadas comparten la misma lista
```

Pero `Depends(get_client)` **no llama** a `get_client`: construye un marcador que FastAPI lee al
arrancar la app para saber qué inyectar en cada request. Que se cree una sola vez es lo correcto.
Salidas: `# noqa: B008` con justificación, o `Annotated` (que elimina la llamada del default).

### `-> CostOut` frente a `-> dict`

Anotar el modelo como tipo de retorno da **tres** cosas:

1. **Serialización** — FastAPI convierte el modelo a JSON. Por eso `.model_dump()` sobra.
2. **Validación de salida** — si intentas devolver algo que no encaja, revienta con 500 *antes*
   de mandarle datos mal formados al cliente. Es una red de seguridad, no un manejador de errores.
3. **Esquema en `/docs`** — la respuesta queda documentada con sus campos y tipos, y eso es lo
   que permite generar clientes automáticamente. Con `-> dict`, `/docs` dice "un objeto".

### Nombrar el valor

`currency.upper()` estaba escrito cinco veces. Una vez es `symbol = currency.upper()`.
Si mañana cambia cómo se normaliza la moneda, se toca **una** línea y no se olvida ninguna —
que es exactamente lo que causó los tres 500 seguidos de la S15.

## S17 (2026-08-26) — `lifespan` y `app.state`

El `lifespan` es el código que corre **una vez al arrancar la app y una vez al apagarla**.

```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    app.state.http_client = httpx.AsyncClient(timeout=2.0)   # ARRANQUE: una vez
    yield                                                     # la app atiende requests aquí
    await app.state.http_client.aclose()                      # APAGADO: una vez

app = FastAPI(title="Model Registry", lifespan=lifespan)
```

El `yield` parte la función en dos: arriba = startup, abajo = shutdown.

**Por qué existe:** hay cosas que deben crearse una sola vez y compartirse durante toda la vida de
la app — un cliente HTTP con su pool, un pool de base de datos. Un endpoint no puede hacerlo:
se ejecuta una vez por request. Con un `AsyncClient` por request se paga handshake TCP+TLS cada vez.

**`app.state`** es el cajón donde se guarda. El lifespan lo llena al arrancar; `get_client` lo lee
en cada request:

```python
def get_client(request: Request) -> httpx.AsyncClient:
    return request.app.state.http_client
```

Sin lifespan, el cajón está vacío. De ahí que en tests `TestClient(app)` a secas no sirva para
endpoints que usan el cliente: hay que usarlo como context manager para que el lifespan corra.

### Traza literal de `GET /models/1/cost?currency=eur`

```python
symbol = currency.upper()            # "EUR"
if model_id not in MODELS: ...       # 1 sí está → sigue
response = await client.get(FRANKFURTER_URL, params={"base": "USD", "symbols": "EUR"})
# → GET https://api.frankfurter.dev/v1/latest?base=USD&symbols=EUR
response.raise_for_status()          # 200 → no lanza
payload = response.json()
# {"amount": 1.0, "base": "USD", "date": "2026-08-26", "rates": {"EUR": 0.85734}}
if "rates" not in payload: ...       # está → sigue
if "EUR" not in payload["rates"]:... # está → sigue
cost_usd = 64000 / 1000 * 3.0        # 192.0
cost     = round(192.0 * 0.85734, 2) # 164.61
```

Salida: `{"id":1,"name":"claude-fable-5","currency":"EUR","rate":0.85734,"cost":164.61}`

En los tests la única diferencia es que `respx` intercepta la llamada a `api.frankfurter.dev` y
devuelve el payload que tú decidas — por eso puedes fijar la tasa y conocer el `cost` de antemano.

### Nits cerrados hoy

- `symbol = currency.upper()` subida **arriba del `try`** y usada también en `params`: un único
  `.upper()` en toda la función.
- El `detail` de la guarda nombra la clave real (`rates`), no la del parámetro enviado.

## Sesión 18 — la cadena completa: por qué existe cada pieza

Las cuatro piezas no son cuatro decisiones sueltas: cada una nace del problema que deja abierta la
anterior.

**Problema 0 — un cliente HTTP por request duele.** Handshake TCP+TLS de ~100-200 ms cada vez;
fuga de sockets (`too many open files` bajo carga); configuración duplicada y divergente. →
Conclusión: **un** cliente compartido.

**Problema 1 — ¿dónde lo creo? → `lifespan`.** A nivel de módulo es malo: nadie lo cierra nunca, y
solo importar el archivo ya abre recursos. Necesitas dos ganchos que solo el servidor puede dar:
"arranqué" y "me muero". Antes eran `@app.on_event("startup")` y `@app.on_event("shutdown")` —
deprecados, y obligaban a una **global** para que el cliente viajara de una a otra.

`lifespan` fusiona ambos en una función partida por un `yield`: arriba el arranque, abajo el
apagado, y el recurso es una **variable local que sobrevive a las dos mitades**. El
`@asynccontextmanager` convierte esa función-generador en un objeto con *entrar*/*salir*: un `with`
que uvicorn abre al arrancar y cierra al parar.

- El `yield` **es** el tiempo en que la app sirve. Por eso `aclose()` va **debajo**: cerrar arriba
  sería entregar un cliente ya cerrado a toda la vida de la app.
- httpx es perezoso: al construir el `AsyncClient` creas el *pool vacío*, no la conexión.

**Problema 2 — ¿dónde lo guardo? → `app.state`.** Un cajón colgado del objeto `app`, para cosas con
vida útil de aplicación, accesible desde cualquier handler vía `request.app`.

**Problema 3 — ¿por qué `get_client` + `Depends` y no leer `app.state` directo?** Funcionaría, pero:

- **Acoplamiento:** así el endpoint *sabe dónde vive* el cliente; si se mueve, tocas 20 endpoints.
  Con la dependencia solo declara *"necesito un `AsyncClient`"*. **Eso es la inyección de
  dependencias:** la función no va a buscar lo que necesita, lo declara y alguien se lo entrega.
- **Sustitución:** `app.dependency_overrides[get_client] = ...` cambia el cliente en tests sin
  tocar el endpoint.
- **La firma es el contrato:** el tipo está a la vista, mypy lo verifica. Con
  `request.app.state.http_client` el tipo es `Any` y nadie verifica nada.
- Y desaparece `Request` de la firma: un endpoint atado al framework pasa a ser función normal.

**Problema 4 — ¿por qué `Annotated[...]` y no `= Depends(...)`?** El estilo viejo
(`client: X = Depends(f)`) usa la ranura del **valor por defecto** para transportar metadatos: le
miente a Python, mypy protesta, y no puedes tener default real y dependencia a la vez.
`Annotated[T, meta]` (PEP 593) pega información extra **a un tipo, sin tocar el valor**: Python
ignora el recado, FastAPI lo lee, la ranura del default queda libre.

**En una línea:** un cliente compartido obliga a un ciclo de vida (`lifespan`), que obliga a un
lugar donde dejarlo (`app.state`), que si se lee directo acopla el endpoint, y de ahí la
dependencia (`get_client` + `Depends`), que necesita no ocupar el default (`Annotated`).

### Error del día: leer un traceback

`NoneType` **no es una excepción** — es un tipo de dato, el de `None`. Solo aparece *mencionado*
dentro del mensaje. **El nombre de la excepción es lo que va antes de los dos puntos:**

```
AttributeError: 'NoneType' object has no attribute 'get'
└─ la excepción ┘└──────── el mensaje ───────────────┘
```

Sin lifespan, `app.state.http_client` **no existe** (no vale `None`, no está): `AttributeError:
'State' object has no attribute 'http_client'`, reventando en `get_client`. Si en cambio valiera
`None`, sería la *misma* excepción pero en otra línea, al hacer `await client.get(...)`. Misma
excepción, distinto sitio — la pregunta útil es siempre **dónde**, no *cuál*.

  "Model not found"}` distingue TU 404 (la guarda del endpoint) del 404
  genérico del router ("Not Found"). Sin eso, el test puede pasar sin que el
  endpoint exista.
- **Prueba de fuego de un test**: si borro la línea que el test dice vigilar y
  el test sigue verde, el test no vigila nada. (Con el arreglo: sin la guarda,
  el request llega al mock 404 → `raise_for_status` → 502 → el test cae.)
- **P2 razonada**: el 404 del upstream se traduce a 502 porque repetirlo
  mentiría — un 404 de `/models/1/cost` le diría al cliente que EL MODELO no
  existe. 502 dice la verdad: "yo estoy bien, el de atrás falló".
- **`@respx.mock` como decorador** compone con `@pytest.mark.parametrize`
  (elección propia del estudiante, válida, alternativa al `with respx.mock:`).

## Regla que queda
- Un mock de respx tiene DOS mitades: registrar la ruta (`respx.get(...).mock`)
  y activar la intercepción (`@respx.mock` o `with respx.mock:`). Sin la
  segunda, los tests tocan la red en silencio.
- Detector barato de mocks muertos: `pytest --durations=3`. Un test mockeado
  corre en microsegundos; décimas de segundo = red.
- Nit abierto (mejora de 2 min): test 5 sin espía (`route.call_count == 1`);
  la prueba de no-red quedó por fuera (durations), no dentro del test.
