# FastAPI — parte 1: primera API real (S10, 2026-08-05)

## Por qué existe
HTTP crudo = parsear texto de un socket. Flask (2010) dio enrutamiento pero
validación y docs quedaban a mano. FastAPI (2018) compone lo ya aprendido:
type hints (contratos) + Pydantic (validación) + async (concurrencia) →
validación automática, serialización a JSON y docs vivas en `/docs`.

## Piezas del día
- **Routing por decorador**: `@app.get("/ruta")` mapea verbo+ruta → función.
  Retornas dict/lista/modelo; FastAPI serializa a JSON (nunca `json.dumps`).
- **Path param tipado**: `{model_id}` en la ruta + `model_id: int` en la firma.
  FastAPI los conecta por nombre y VALIDA: `/models/abc` → 422 con
  `loc: ["path", "model_id"]` sin que la función se ejecute.
- **Body**: argumento tipado con un modelo Pydantic (`model: ModelIn`) = body
  del request. Llega ya validado y construido; nunca se parsea JSON a mano.
- **Errores**: `raise HTTPException(status_code=404, detail="...")` convierte
  excepción → respuesta HTTP. Validación fallida → **422** (no 400: el 400 es
  request malformado; 422 = JSON bien formado, contenido inválido) con el
  formato `loc`/`msg` de Pydantic.
- **Status de éxito en el decorador**: `@app.post("/models", status_code=201)`.
  201 Created = "ok y creé un recurso". Es parte de la DEFINICIÓN del endpoint
  (por eso va en el decorador y aparece en /docs). Solo camino feliz: 404/422
  mandan sobre él.
- **POST devuelve lo creado** incluyendo el `id` que asignó el servidor —
  si no, el cliente no sabe cómo pedir su recurso después.
- **`/docs`**: Swagger interactivo generado del código real (decoradores,
  firmas, modelos). No puede mentir porque no se escribe aparte.

## uv en serio (deuda S6 cobrada)
- `uv init --bare` → solo `pyproject.toml` (lo que PIDES: deps, requires-python).
- `uv add "fastapi[standard]"` → declara en pyproject + resuelve en `uv.lock`
  (lo que RESULTÓ: versiones exactas, transitivas) + instala en `.venv/`.
- `uv run fastapi dev main.py` → corre con el entorno del proyecto, reload
  automático. `.python-version` fija el Python POR PROYECTO (fix de raíz del
  problema pyenv/python3 del sistema).
- Lock nunca se edita a mano; `.venv/` nunca se commitea.

## Python del día
- Desempaque de dicts: `{"id": 7, **model.model_dump()}` funde los pares al
  mismo nivel. Clave repetida: gana la de más a la derecha.

## Errores y lecciones del día
- Asignación ingenua de ids: `max(MODELS.keys()) + 1` → con store vacío,
  `ValueError` no atrapado = 500; y al borrar el id más alto, el siguiente
  POST RECICLA el id (cliente con referencia vieja recibe datos ajenos con
  200 en vez de 404). Sistemas reales: contador monotónico (auto-increment).
- Higiene de predicciones: la hipótesis original se conserva y se ANOTA abajo
  (incluso "primera intuición X / tras pensarlo Y") — no se reescribe.
