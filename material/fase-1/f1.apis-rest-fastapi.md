# FastAPI — parte 1: primera API real (S10, 2026-08-05)

## Por qué existe
HTTP crudo = parsear texto de un socket. Flask (2010) dio enrutamiento pero
validación y docs quedaban a mano. FastAPI (2018) compone lo ya aprendido:
type hints (contratos) + Pydantic (validación) + async (concurrencia) →
validación automática, serialización a JSON y docs vivas en `/docs`.

## Piezas del día
- **Routing por decorador**: `@app.get("/ruta")` mapea verbo+ruta → función.
  Retornas dict/lista/modelo; FastAPI serializa a JSON (nunca `json.dumps`).
- **Path param tipado**: `{model_id}` en la ruta + `model_id: int` en la firma.
  FastAPI los conecta por nombre y VALIDA: `/models/abc` → 422 con
  `loc: ["path", "model_id"]` sin que la función se ejecute.
- **Body**: argumento tipado con un modelo Pydantic (`model: ModelIn`) = body
  del request. Llega ya validado y construido; nunca se parsea JSON a mano.
- **Errores**: `raise HTTPException(status_code=404, detail="...")` convierte
  excepción → respuesta HTTP. Validación fallida → **422** (no 400: el 400 es
  request malformado; 422 = JSON bien formado, contenido inválido) con el
  formato `loc`/`msg` de Pydantic.
- **Status de éxito en el decorador**: `@app.post("/models", status_code=201)`.
  201 Created = "ok y creé un recurso". Es parte de la DEFINICIÓN del endpoint
  (por eso va en el decorador y aparece en /docs). Solo camino feliz: 404/422
  mandan sobre él.
- **POST devuelve lo creado** incluyendo el `id` que asignó el servidor —
  si no, el cliente no sabe cómo pedir su recurso después.
- **`/docs`**: Swagger interactivo generado del código real (decoradores,
  firmas, modelos). No puede mentir porque no se escribe aparte.

## uv en serio (deuda S6 cobrada)
- `uv init --bare` → solo `pyproject.toml` (lo que PIDES: deps, requires-python).
- `uv add "fastapi[standard]"` → declara en pyproject + resuelve en `uv.lock`
  (lo que RESULTÓ: versiones exactas, transitivas) + instala en `.venv/`.
- `uv run fastapi dev main.py` → corre con el entorno del proyecto, reload
  automático. `.python-version` fija el Python POR PROYECTO (fix de raíz del
  problema pyenv/python3 del sistema).
- Lock nunca se edita a mano; `.venv/` nunca se commitea.

## Python del día
- Desempaque de dicts: `{"id": 7, **model.model_dump()}` funde los pares al
  mismo nivel. Clave repetida: gana la de más a la derecha.

## Errores y lecciones del día
- Asignación ingenua de ids: `max(MODELS.keys()) + 1` → con store vacío,
  `ValueError` no atrapado = 500; y al borrar el id más alto, el siguiente
  POST RECICLA el id (cliente con referencia vieja recibe datos ajenos con
  200 en vez de 404). Sistemas reales: contador monotónico (auto-increment).
- Higiene de predicciones: la hipótesis original se conserva y se ANOTA abajo
  (incluso "primera intuición X / tras pensarlo Y") — no se reescribe.

# FastAPI — parte 2: API key + mypy (S11, 2026-08-06)

## Por qué existe la API key
Sin auth, cualquiera con la URL escribe en tu API. Antes: confianza en la red
o Basic Auth (user:pass, pensado para humanos). Para máquina-a-máquina se
impuso lo simple: secreto estático en un header (convención `X-API-Key`) que
el servidor compara. Es el esquema de OpenAI/Anthropic/Stripe.

## Piezas del día
- **Inyección de dependencias (`Depends`)**: la función declara lo que
  necesita y FastAPI se lo trae. `dependencies=[Depends(verify_api_key)]` en
  el decorador = portero que corre ANTES del handler; si lanza, el handler
  nunca se ejecuta. Encadenable: endpoint → verify_api_key → api_key_header.
- **`APIKeyHeader(name="X-API-Key", auto_error=False)`**: objeto *callable*
  (clase con `__call__`) que solo EXTRAE el header del request. Se construye
  una vez al importar; FastAPI lo llama por request. `auto_error=False` →
  header ausente = `None` (tú decides el error, 401); con `True`, FastAPI
  rechaza solo con un 403 genérico. Verificado leyendo el código fuente.
- **El portero**: primero `if key is None → 401`, después
  `secrets.compare_digest(key, expected)` → 401 si no coincide; si coincide,
  la función termina sin más y el request pasa.
- **`compare_digest` vs `==`**: `==` corta en la primera diferencia → el
  tiempo de respuesta filtra la key carácter a carácter (timing attack).
  `compare_digest` tarda siempre lo mismo. Secretos → compare_digest.
  Explota con `None` (TypeError) — de ahí el None-check previo.
- **Key desde el entorno**: `os.environ["MODEL_REGISTRY_API_KEY"]` a nivel de
  módulo → si falta, el arranque MUERE (correcto: API "protegida" sin key
  configurada es peor que API caída). `os.environ` es `dict[str, str]`:
  las env vars siempre son strings.
- **DELETE**: `status_code=204` (sin body, la función devuelve None) + 404
  reutilizando el mismo criterio del GET.
- **/docs**: `APIKeyHeader` se registra como security scheme en el OpenAPI →
  botón *Authorize* automático; POST y DELETE marcados con candado.

## mypy (deuda de f1.python-profesional COBRADA)
- `uv add --dev mypy` (grupo dev, no producción) + `uv run mypy main.py`.
- Narrowing: tras `if key is None: raise`, mypy sabe que `key: str` y permite
  `compare_digest`. El chequeo de seguridad y el de tipos son EL MISMO.

## Errores y lecciones del día
- **El 500 fantasma (P1)**: primera versión sin None-check → `compare_digest(None, str)`
  → `TypeError` → 500. Exactamente el bug que mypy marca en `str | None`.
  Diagnosticado y corregido por el estudiante.
- **PowerShell**: `curl` es alias de `Invoke-WebRequest` → usar `curl.exe`;
  comillas JSON escapadas `\"`; env vars con `$env:NAME = "..."`, no `export`.
- P2 (reciclaje de ids al borrar el más alto) predicha BIEN — lección de S10
  asentada. `max(keys, default=0)` tapa el 500 del store vacío, no el reciclaje.
