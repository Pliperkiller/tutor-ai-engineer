## Concepto

Tu API como **cliente** de otra API. Tres problemas nuevos y su herramienta:
1. dónde vive el cliente HTTP → `lifespan` + `app.state` (un `AsyncClient` compartido; uno
   por request tiraría el pool de la S9). Antes: `@app.on_event`, hoy deprecado.
2. qué status devolver cuando el que falla es el otro → **502** (upstream respondió error)
   y **504** (upstream no respondió). Dejar escapar la excepción daría un 500 mentiroso.
3. cómo testearlo sin red → respx + `with TestClient(app) as client:` (respx no intercepta
   el transporte ASGI, así que solo se finge la llamada saliente).

Demo ejecutable `demo_upstream.py` en 5 partes: corrió y mostró 200 / 502 / 504.
